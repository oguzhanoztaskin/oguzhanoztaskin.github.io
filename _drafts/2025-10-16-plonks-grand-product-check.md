In our [last post]({% post_url 2025-11-07-kzg-batching-in-plonk %}), we developed a powerful tool: a way to prove that a polynomial equation holds true over an entire domain `H` using the vanishing polynomial trick. This allows us to compress many checks into a single, efficient proof.

Now, we're ready to tackle the main event: Plonk's permutation proof {% cite gabizon2019plonk %}. At its heart, Plonk is a protocol for proving arithmetic circuits. A key part of this is proving that the values on the "wires" of the circuit are correctly copied. For example, the output of gate 5 might be the input to gate 12. This is fundamentally a permutation argument: we need to prove that the values on one set of wires are a permutation of the values on another set.

In this post, we'll dive into the clever algebraic construction Plonk uses to represent this permutation claim. We will transform the permutation problem into a couple of polynomial equations that we can then prove using the methods we already know.

## Preliminaries

Some definitions we'll be using, in addition to the ones from previous posts:

- **Cyclic Group Generator**: We'll use a multiplicative cyclic group `H` of size `n`, generated by `ω`. Therefore, $H = \{\omega^0, \omega^1, \dots, \omega^{n-1}\}$.

- **Lagrange Basis Polynomials**: $L_i(X)$ is the `i`-th Lagrange basis polynomial for the domain `H`. It has the property that $L_i(\omega^j) = 1$ if $i = j$, and $0$ otherwise. We'll specifically need $L_1(X)$, which corresponds to the first element of our domain, $\omega^0=1$.

- **Permutation**: We are given a public permutation $\sigma: [n] \to [n]$, where $[n] = \{0, 1, \dots, n-1\}$.

## The Permutation Claim

Let's say we have two secret polynomials, $f(X)$ and $g(X)$. Our goal is to prove that the evaluations of $f(X)$ over the domain $H$ are a permutation of the evaluations of $g(X)$.

More formally, for a given public permutation $\sigma$, we want to prove:
$$
\forall i \in [n], \quad f(\omega^i) = g(\omega^{\sigma(i)})
$$
This means that the set of values $\{f(\omega^0), \dots, f(\omega^{n-1})\}$ is the same as the set $\{g(\omega^0), \dots, g(\omega^{n-1})\}$, just possibly in a different order defined by $\sigma$.

How can we prove this? A first idea might be to check if the products of the values are equal:
$$
\prod_{i=0}^{n-1} f(\omega^i) \stackrel{?}{=} \prod_{i=0}^{n-1} g(\omega^{\sigma(i)}) = \prod_{j=0}^{n-1} g(\omega^j)
$$
This is a good start, but it has a major flaw: it can't tell the difference between the image sets $\\{1, 6\\}$ and $\\{2, 3\\}$, since both sets multiply to 6. We need something more robust.

## The Grand Product Check

Plonk's solution is to build a "running product" or **accumulator**. The idea is to build a product term by term, and check that it behaves as expected.

First, to handle the problem of duplicate values (like $\\{2, 2\\}$ and $\\{2, 2\\}$), the verifier provides two random challenge scalars, $\beta$ and $\gamma$. The prover then "blinds" the polynomials $f$ and `g` by incorporating these random values along with the permutation information. We won't go into the full details of how the permutation polynomials `S_ID(X)` and `S_σ(X)` are used here, but the result is two new sets of values that are extremely unlikely to have duplicates or accidental relations. The core idea is that we check the equality of fractions:

$$
\prod_{i=0}^{n-1} (f(\omega^i) + \text{randomness}) \stackrel{?}{=} \prod_{i=0}^{n-1} (g(\omega^{\sigma(i)}) + \text{randomness})
$$
If this holds for random challenges, the underlying values must be a permutation.

To turn this into a protocol, the prover constructs an accumulator polynomial, $Z(X)$, that keeps track of this running product. It is defined recursively over the domain $H$:
1.  **Start at 1:** The accumulator starts with a value of 1 before any terms are included.
    $Z(\omega^0) = 1$

2.  **Recursive Step:** At each step `i`, it multiplies in the next term from the `f` values and divides out the next term from the `g` values.
    $$
    Z(\omega^{i+1}) = Z(\omega^i) \cdot \frac{f(\omega^i) + \dots}{g(\omega^{\sigma(i)}) + \dots}
    $$

If the permutation claim is true, then over the entire domain, every value multiplied into the accumulator will be eventually divided out. This means that after processing all `n` elements, the accumulator should return to its starting value of 1.

## From Recurrence to Polynomial Equations

This is a powerful idea, but it's defined point-by-point. We need to express these conditions as polynomial identities that hold over the entire domain `H`.

**Condition 1: The starting point.**
We need to enforce that $Z(\omega^0) = 1$. We can write this as a polynomial equation using the first Lagrange basis polynomial, $L_1(X)$:
$$
L_1(X)(Z(X) - 1) = 0, \quad \text{for all } X \in H
$$
This works perfectly because $L_1(X)$ is 1 at $X=\omega^0$ (forcing $Z(\omega^0)-1=0$) and is 0 for all other points in $H$ (where the equation becomes $0 \cdot (\dots) = 0$, which is trivially true).

**Condition 2: The recursive step.**
We need to enforce the recurrence relation for (almost) all points in $H$. Let's simplify the notation from the paper for clarity and say our randomized values are from polynomials $f'(X)$ and $g'(X)$. The relation is:
$$
Z(X \cdot \omega) = Z(X) \cdot \frac{f'(X)}{g'(X)}
$$
To get rid of the division, we can rearrange this to:
$$
Z(X \cdot \omega) \cdot g'(X) - Z(X) \cdot f'(X) = 0, \quad \text{for all } X \in H
$$
This single polynomial equation enforces that the accumulator is built correctly at every single step.

## Conclusion

We did it! We have successfully transformed a complex claim about permutations into two (relatively) simple polynomial equations that must evaluate to zero across our entire domain `H`:

1.  $L_1(X)(Z(X) - 1) = 0$
2.  $Z(X \cdot \omega)g'(X) - Z(X)f'(X) = 0$

The prover's task is now to convince the verifier that they know a secret polynomial $Z(X)$ that satisfies these two equations.

This sets us up perfectly for the final step. In the next post, we will combine these two equations into one, and then use the vanishing polynomial technique from our last post to create a single, efficient, and final proof.
